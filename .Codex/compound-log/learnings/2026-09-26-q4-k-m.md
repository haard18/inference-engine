# 2026-09-26 - Mixed Q4_K_M checkpoint

**Context:** The official SmolLM2-135M Q4_K_M GGUF checkpoint has 272 tensors. It contains 61 f32 vectors, 61 Q5_0 matrices, 120 Q8_0 matrices, and 30 Q4_K matrices. Q4_K_M is a mixture of quantization formats, not one tensor format. The Q5_0 and Q4_K tensors need separate block decoders.

**Learning:** Q5_0 stores 32 signed five-bit values behind one f16 scale in 22 bytes. Q4_K stores 256 values in 144 bytes, with a shared scale and minimum plus eight packed six-bit subscales and minima. The existing f32 activation path can consume both while retaining the compact blocks in memory. Loading Q4_K alone would leave the official Q4_K_M checkpoint unusable.

**Evidence:** An independent NumPy implementation produced first twelve scores `[17.496885, 1.248975, 1.396863, 1.565452, 2.047933, 1.332554, 4.086927, 1.332554, 1.332554, 1.332554, 1.332554, 1.332554]` after token IDs `[1, 2, 3]`; the Rust engine matched each score within `1e-3` and selected token `30`. Small matrix tests check Q5_0 high-bit unpacking and Q4_K subscales. The downloaded file was 101,016,128 bytes and its SHA-256, `e3131339bf4e8065265593d4fd8f7bb7ff2d3abff1edb5618aa1197b89cad9f5`, matched the repository's linked ETag.

**Memory:** On one Apple Silicon Mac, one token for the same text prompt used 119,832,576 bytes peak resident memory with Q4_K_M and 162,447,360 bytes with Q8_0. These are single local measurements. They do not establish throughput or output quality for other prompts.
