# 2026-09-26 - Reusable conversation checkpoints

The child model process now retains the model's key/value attention state at the end of a completed request's input prompt. Before generating, it records the current position and next-token scores. After generation, it truncates the newly generated attention state and restores those scores. A later request with the same conversation ID reuses that checkpoint only if the new tokenized prompt starts with the saved token sequence exactly. It evaluates only the suffix. If the prefix differs or the cache entry is gone, it evaluates the full prompt. This exact token check avoids assuming that decoded assistant text retokenizes to the same IDs as the sampled output.

A conversation ID consists of a device UUID and a random UUID. The API returns it in `x-inference-conversation-id`; clients send it back with full message history. It acts as an unguessable capability within the owner's authenticated device pool. The coordinator sends follow-ups to the owning device while it has room. If that device is lost, another worker recomputes from full history and returns a new device-owned ID. The peer API rejects a conversation ID owned by a different device.

Each child caches at most eight prompt checkpoints and 128 MiB of allocated checkpoint data. It evicts the least recently used checkpoint to make room and lazily removes entries older than five minutes on the next cache access. A child restart clears the cache; an unchanged ID then causes full recomputation. Ordinary responses report the exact reused prefix length in `usage.prompt_tokens_details.cached_tokens`.

A real-model CPU test confirmed full reuse for a repeated prompt, partial reuse for an extended history, no reuse after a changed prefix, and eviction after the entry limit. A Metal test confirmed repeated prompt reuse and matching output on that backend. A two-device test first routed work to an idle peer, then confirmed a follow-up stayed on that peer after the local device recovered. After the peer was stopped, the same full prompt ran locally and received a new owner ID. Model splitting and performance measurements remain open.
